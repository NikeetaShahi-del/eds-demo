## Step 3: Cross-file consistency validation

### Tabs block example

**component-definition.json:**
```
id: "tabs"
template.name: "Tabs"
template.filter: "tabs"
```

**component-models.json:**
```
id: "tabs-item" (child item model)
fields: [title, content_heading, content_headingType, content_image, content_richtext]
```

**component-filters.json:**
```
id: "tabs"
components: ["tabs-item"]
```

**Real block at blocks/tabs/tabs.js:**
```javascript
export default async function decorate(block) {
  const tablist = document.createElement('div');
  tablist.className = 'tabs-list';
  tablist.setAttribute('role', 'tablist');
  
  const tabHeadings = [...block.children]
    .filter((child) => child.firstElementChild
      && child.firstElementChild.children.length > 0)
    .map((child) => child.firstElementChild);
  
  tabHeadings.forEach((tab, i) => {
    const tabpanel = block.children[i];
    tabpanel.className = 'tabs-panel';
    // ... reads child divs which map to model fields
  });
}
```

**Mapping check:**
- The `decorate()` function reads `block.children` (tab items)
- Each child is expected to have divs (one per model field)
- Field order in the JCR will match the order of `<div>` elements in the authored content
- Field names in component-models.json (`title`, `content_heading`, etc.) correspond to the structure the `decorate()` function processes

✓ **CONSISTENCY VERIFIED**

## Step 4: Field naming pattern analysis

### Observed naming conventions

From `component-models.json` field `name` values:

**Simple single-word fields:**
```
name
title
image
link
text
index
```

**Compound fields with underscores (hierarchical naming):**
```
media_image          → image-related field within "media" namespace
media_imageAlt       → alt text for media image
content_text         → text within content
content_heading      → heading within content
content_headingType  → heading type (H3-H6) within content
content_image        → image within content
content_richtext     → rich text within content
```

**Observation:**
The underscore pattern (`namespace_property`) is used for:
- Grouping related fields logically
- Matching the DOM structure (nested divs)
- Improving readability in the component model

**This pattern works because:**
1. Authors don't directly see the `name` property; they see the `label`
2. The `name` property is used by the `decorate()` function to extract field values from DOM divs
3. The hierarchy matches the content tree structure in the UE

✓ **NAMING PATTERN IS CONSISTENT AND LOGICAL**

   - Add new field entry to the model in component-models.json
